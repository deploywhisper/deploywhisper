# DeployWhisper v1.5.0 — release candidate notes

Status: **candidate; not yet publicly released**.

DeployWhisper v1.5.0 adds InfraFlow: bounded evidence-gated infrastructure
preflight workflows that preserve the local-first, advisory-first analysis core.
DeployWhisper still does not apply, destroy or remediate infrastructure.

## InfraFlow

- Versioned immutable workflows, typed inputs/references and bounded execution.
- Verified local human identity, project/workspace membership and explicit
  evidence-bound decisions with acknowledgement/shared-review modes.
- Durable fenced SQLite orchestration, cancellation, retries and unknown-delivery
  reconciliation without blind resend.
- Isolated OpenTofu collection with screened transport, protected local exact-byte
  custody, permanent advisory reports and Evidence Law parity.
- Registered targets, one-use handoff grants, durable receiver consume/receipt
  records and conservative locks.
- Default-off co-located material authority with an Ed25519-signed monotonic
  ledger and live split-process verification of protected exact-plan bytes.
- Declared unit preflight, signed trigger intake and shared UI/API/CLI surfaces.
- Retention, quiesced backup/restore, restore epochs, restricted-network operation,
  metrics, troubleshooting and operator recovery procedures.

## Supported profile

The qualified matrix is intentionally narrow. See
[InfraFlow v1.5.0 supported profile](../infra-automation/support.md) for exact
application, runner, tool, receiver, identity and platform versions plus exclusions.
OpenTofu/Terraform licensing remains independent and operator-managed.

Epic 17 Live Environment Grounding is not part of v1.5.0; it returned to its
independent v1.6.0 release train before any implementation shipped.

## Security and integrity

- Source assets include deterministic archive, source manifest, SPDX2.3 source
  dependency SBOM and SHA-256 checksums. A separate bounded runner source archive
  and manifest identify its entrypoint and exact inventory without bundling tools.
- Release workflows require exact tag/source identity and native GitHub artifact
  and OCI provenance verification before publication or alias promotion.
- Runner and receiver credentials remain separate from human authority. Raw
  infrastructure state, credentials and saved plans are never public artifacts.

## Qualification and known limitations

Automated qualification covers full CI, crash/recovery and authorization corpora,
real isolated OpenTofu collection, actual TLS runner/report journeys, composed
browser accessibility and the declared reference performance allocation.

The independent human self-service pilot was **not executed**. The accountable
maintainer approved a release-specific waiver after reviewing the technical
evidence and accepted the residual runbook-usability risk. This waiver is not
human pilot evidence. The final public release still requires independently
verified signed app/runner artifacts and explicit publication authorization.

## Upgrade

Back up the coordinated SQLite database, artifact roots and protected custody
while writers are quiesced. Follow the [operator procedures](../infra-automation/operations.md)
and [core data lifecycle guide](../operations/data-lifecycle.md). Restore advances
the installation epoch and invalidates old sessions, grants, runner credentials
and leases until reconciliation. Retain v1.4.0 and its backup until verification
and rollback checks complete.
