# Accepted/unknown receiver proof: composition gap and repair

**Historical gap — repaired in the current working tree.** Read-only inspection and a direct default-service probe found
missing production composition before any receiver browser fixture was created.
The default material lookup returns503, and the registry contains only uploaded
intake/shared analysis (plus admitted collection when explicitly configured).
See [the structured evidence](composition-gap.json).

## Required implementation before a production-path claim

1. A server-installed material resolver must derive the exact binding, report,
   collected provenance, policy, registered target and custody facts from actual
   retained data and the qualified operator domain. An HTTP caller must never
   provide trusted eligibility flags.
2. The operator-domain witness must atomically supply durable monotonic material
   generations and a reset identity. The existing contract explicitly forbids
   substituting inferred hashes/epochs or a constant fixture generation.
3. Compose policy/decision/handoff execution with the coordinator and existing
   service transactions, preserving human review and durable one-use intent.
4. Then exercise actual collection, two authenticated shared-review identities,
   actual decision/handoff transitions and a separate durable ReferenceReceiver.
   Its raw plan custody remains outside the app. A fixed non-destructive local
   qualification action and intentionally lost response can test retained unknown
   state and no-blind-resend behavior, explicitly without qualifying GitHub delivery.
5. Browser cancellation/reconciliation must observe those actual transitions;
   seeding terminal rows or reusing synthetic material flags is not this proof.

Existing approval/outcome fixtures install synthetic material providers and seed
engine states. They are intentionally bounded contract/UI evidence. Reusing them
would not close the stronger continuous real-runner accepted/unknown obligation.
Production GitHub dispatch additionally needs registered installation credentials,
workflow identity and explicit action authority; none was assumed or requested here.

The approved co-located repair adds a signed monotonic material ledger, public-key-
only app verifier, live Ed25519 Unix custody challenge, exact retained-fact binding,
fixed policy worker and one shared decision/handoff service composition. The app
rejects private signing-key/raw-custody configuration. The separate authority
process verifies the protected descriptor/bytes on every material read.

Current integration proof exercises actual `ProtectedCustody`, operator CLI ledger
publication, two verified humans, durable non-destructive handoff preparation and
revocation/generation denial. Public GitHub dispatch remains separately credentialed
and is not inferred from the local receiver proof.
