# Disposable live GitHub qualification

Install `receiver.yml` and `qualify.yml` as `.github/workflows/` files in the dedicated **deploywhisper/receiver-smoke-consumer** repository. These are inert source templates in DeployWhisper. Protect sandbox `main`, enforce protection for administrators, disable force pushes/deletion, and retain the protected commit SHA. Run the qualifier at that `main` commit after reviewing the immutable app commit containing `scripts/qualify_github_receiver.py`.

```sh
gh workflow run qualify.yml --repo deploywhisper/receiver-smoke-consumer --ref main -f app_commit=REVIEWED_40_HEX_APP_COMMIT
```

The qualifier has one input, a checked 40-character lowercase app commit SHA. Repository, API origin, workflow and protected ref are fixed in code. Checkout and setup-python actions use reviewed immutable upstream SHAs. Checkout does not persist credentials. Only the five Pydantic dependency packages already version/hash pinned in the reviewed app requirements lock are installed.

The job's ephemeral repository-scoped `GITHUB_TOKEN` has only `contents: read` and `actions: write`; it is explicitly passed as `SANDBOX_DISPATCH_TOKEN` to a process-local `sandbox-ephemeral-dispatch` credential reference. No ambient `gh` authentication, operator PAT, repository secret, infrastructure credential, grant bearer, raw artifact bytes, or persistent credential store is used. The app repository must be public so the sandbox token can check out its reviewed commit.

`python -m scripts.qualify_github_receiver` requires the standard Actions environment (`GITHUB_ACTIONS`, `GITHUB_REPOSITORY`, `GITHUB_REF`, `GITHUB_EVENT_NAME`, `GITHUB_SHA`, `GITHUB_RUN_ID`, `GITHUB_RUN_ATTEMPT`, `RUNNER_TEMP`, optional `GITHUB_STEP_SUMMARY`), plus `APP_COMMIT` and `SANDBOX_DISPATCH_TOKEN`. It accepts only first-attempt manual runs on sandbox main. `GITHUB_SHA` supplies the expected immutable receiver workflow revision. Numeric repository/workflow IDs and the protected main SHA are resolved through the same closed pinned HTTPS transport; the actual adapter independently revalidates identity and protection immediately before its only POST. Source provenance uses fresh synthetic collected/custody timestamps bounded to ten minutes, with a deliberately different synthetic source commit from the receiver workflow commit. This typed synthetic decision is qualification data, never production approval or receiver authority.

The receiver accepts exactly `operation_id` and `binding_digest`. It runs a fixed acknowledgment echo with no checkout, input interpolation, credentials, infrastructure command, or receiver-consume claim. The actual adapter's accepted DTO proves an HTTP 200 dispatch with correlated run ID and exact API/web URLs. The qualifier prints safe acceptance and completed observation DTOs to the log and Actions summary, with a run link; it uploads no artifact. It polls for at most five minutes with ten-second per-request deadlines. Workflow success is GitHub evidence only: receiver consume, execution, deployment, and reconciliation remain **not established**.

Concurrency serializes qualifier jobs. Actions reruns (`GITHUB_RUN_ATTEMPT > 1`) fail before checkout or dispatch; a local exclusive marker is written before the one dispatch attempt and retained on failure. No POST is retried. If any acceptance is uncertain, inspect existing run evidence and resolve manually; never rerun/resend that operation. A fresh manual qualifier invocation is a separately authorized synthetic operation, not recovery of an uncertain prior operation. Retain safe run URLs/DTOs and branch protection metadata in the Story 16.11 qualification record. The root operator owns repo creation, protection, dispatch, and eventual disposal.
