# Qualification threat model

Date: 2026-11-12. Scope: design review and disposable offline prototypes, not independent security sign-off or production qualification.

| Boundary / threat | Required disposition | Qualification limit |
| --- | --- | --- |
| Plan or project configuration chooses a role/account/endpoint, causing a confused deputy or SSRF | Reject endpoint, host, role ARN, account override, credential parameters and unknown keys before session creation. Only trusted operator configuration selects an ambient profile; validate returned account against the authorized scope before resource reads. | Offline config corpus; real SDK session/endpoint resolution remains unqualified. |
| Ambient instance role grants a web user host privileges | Do not expose the unrestricted provider chain to project callers. Default-deny IMDS, container endpoints and credential_process on shared hosts; operator-only explicit mechanism selection, scope binding and process/network isolation required. Opting in a project is insufficient authority. | Resolved initial mechanism decision: environment only by default, trusted operator-selected shared credentials opt-in; all other providers removed before lookup. SDK probes execute this boundary. Product security review remains required before17.3. |
| Environment overrides redirect otherwise canonical SDK calls | Ignore/reject AWS_ENDPOINT_URL and service endpoint overrides, custom CA/proxy settings from untrusted inputs; operator proxy trust must be explicit. Region/partition validation uses SDK metadata, never a caller URL. | Pinned real SDK probes verify canonical endpoints, TLS verification, no implicit proxies, ignored endpoint/CA overrides and installed-package-only model loading; actual live transport qualification remains17.3. |
| Credentials leak through errors, logs or snapshots | Use existing services/content_security.py; never serialize the credential object or exception payload. Screen every emitted field; redact before digest/persistence. | Synthetic secret corpus is limited; no product API/snapshot exists in this story. |
| Read-only APIs disclose sensitive data | Allow-list membership and a read verb alone do not establish safety: exclude GetSecretValue, GetParameter values, S3 object bodies, Lambda code/environment and user data. Minimize retained fields to explicitly selected facts. | Freeze exact safe response fields and redaction masks per family before production collection. |
| Resource identifiers and topology reveal the estate | Treat snapshots as sensitive project evidence, mask account identifiers, restrict report/export access and backups. Never retain raw plans or raw provider responses. | No real identifiers, state or snapshots are committed. |
| Read collection exhausts budget or hangs | Apply deadline/cancellation at dispatch, per-call timeouts and bounded retries within the same deadline; count attempts, expansion, pagination and retries against budget. | Fake-provider benchmark measures scheduling only; real latency, throttling and cancellation remain unqualified. |
| Purging retained evidence invalidates grounded claims | Adopted policy: seven days unreferenced from observation, extended by report evidence lifetime; retain snapshot while any report references its digest; purge payload only after references expire, preserve nonsecret digest/provenance tombstone, mark missing evidence explicitly. Imported snapshots follow the same rule. | Adopted reference-bound seven-day unreferenced retention decision; five executable decision tests. Product storage/purge tests remain17.1; no Epic16 protocols. |

The SDK documentation confirms that the ambient chain can fall through to host metadata and supports external credential mechanisms. Therefore enabling a generic session is insufficient on a shared host. See [AWS credential chain](https://docs.aws.amazon.com/boto3/latest/guide/credentials.html) and [IMDS credential provider](https://docs.aws.amazon.com/sdkref/latest/guide/feature-imds-credentials.html). The adopted initial mechanism restrictions resolve shared-host escalation for this qualification profile; unsupported mechanisms remain default-deny until separately qualified.

Action equality between a prototype and its IAM policy proves only action-set equality, not resource-level least privilege or AWS authorization success. Service-specific scoping must follow the [AWS Service Authorization Reference](https://docs.aws.amazon.com/service-authorization/latest/reference/list_ec2.html). No production policy is qualified here.
