## Closed wire and resource policy

Every object rejects unknown fields; protocol version is a strict integer 1, never a boolean or string. Version defaults materialize to 1 inside typed nested objects; canonical bindings include these defaults, including explicit null optional fields. Unsupported major, step kind, capability, authorization or state denies without removing a safety requirement. This v1 registry has uploaded intake, admitted collection, shared analysis, policy evaluation, human decision and registered GitHub handoff. It contains no command, expression, shell, plugin, apply or destroy step. Opaque IDs are 1–128 ASCII alphanumeric/underscore/dot/colon/hyphen characters and cannot contain substitution text.

Workflow JSON/YAML and each wire message are at most **128 KiB UTF-8**, nesting at most **16**, at most **50 steps**, and no YAML anchors, aliases, merge keys, duplicate keys, cycles or implicit timestamp objects. Byte/depth/alias checks occur before constructing YAML; safe loading then typed validation follows. The 128 KiB ceiling accommodates the measured 50-step synthetic fixture with wide headroom and prevents large input from reaching parser construction. Depth 16 exceeds the actual fixture's nested binding needs but prevents recursion/resource growth. Qualification tests admit the exact byte/50-step boundaries and reject one beyond. These are measured bounded examples, not throughput/denial-of-service certification.

All dependencies are **AND prerequisites**: a step can run only after every declared prerequisite succeeds. There are no conditional/OR branches in v1. References must identify a transitive successful prerequisite with the exact output type. Analysis consumes screened artifacts; policy consumes its exact report; human decision consumes its gate's action binding; handoff consumes the same binding and that decision's receipt. Every handoff has successful matching gate and decision ancestry, target and authorization. Exact-plan workflows require admitted collection as their report's artifact ancestor. Runtime 16.5/16.8 must additionally check successful states, current immutable evidence and decision freshness; structural qualification grants no authorization. Intake/collection parameters are only strict positive safe-integer `max_artifact_bytes` (≤8 MiB) and `timeout_seconds` (≤600); arbitrary parameters are rejected.

Runner logs are ≤**16 KiB UTF-8 per chunk** (byte bound as well as character bound). Upload envelopes contain screened digest and atomic upload ID, never raw plan/state. The server recomputes transport digest; completed upload ID must resolve to that exact current fenced attempt before completion. The schema alone cannot prove an ID resolves; SQLite/collector implementations must enforce it transactionally. Each claim/heartbeat/log/upload/complete includes runner/project/workspace/run/step, monotonic attempt/fence, coordinator generation, authorization/restore epochs, lease deadline, exact profile digest, capability registry, sequence and `runner-task-v1` audience. Enrollment uses independent one-use `runner-enrollment-v1`; enrollment expiry/consume durability belongs to 16.12. A task credential cannot enroll or acquire human capabilities. Unknown capabilities deny negotiation.

UTC timestamps use exactly `YYYY-MM-DDTHH:MM:SSZ` and must be real dates. Collected evidence expires within 60 minutes; decision/lease/custody policies may shorten but never extend evidence. Integer numbers are limited to ±(2^53−1); schema quantities are positive except cursor zero. NaN, infinity, fractions and boolean numeric quantities deny. No timezone guessing or lossy float tuple serialization.

## Source, custody and hash identity

Uploaded source explicitly says repository/immutable commit unavailable, includes that limitation, has no invented SHA or custody, and is advisory only. Collected source identifies registered repository, immutable 40-hex IaC commit, authenticated collector, exact admitted profile, screened transport digest/redaction version and collection/deadline. Pipeline repository/workflow/immutable revision are separate from IaC identity. Exact-plan provenance additionally carries an opaque protected-custody handle, **raw-local** SHA-256 and expiry; raw plan/state never belongs in the application, public fixture or transport. Synthetic fixture digest strings are representative syntax and confer no trust. Real selected profile/custody evidence is bound separately in WP4/WP5.

`tuple-json-utf8-v1` is lexicographically sorted string-key JSON, compact separators, UTF-8, `ensure_ascii=False`, `allow_nan=False`, no BOM, no trailing newline, no Unicode normalization, safe integer numbers only. Array order remains significant. Inputs are typed and closed before canonicalization. SHA-256 is encoded `sha256:` plus 64 lowercase hex. Canonicalization materializes the typed model's defaults/nulls exactly. Mutating any bound field requires a new tuple digest and fresh evidence/decision; canonical key reorder is identical, composed/decomposed Unicode is deliberately different. Workflows hash their validated immutable published representation, never editor whitespace.

Report snapshots use **`report-export-bytes-sha256-v1`**: capture the existing `services/report_service.py::_serialize_report` report-only payload once in the new future-16.8 snapshot exporter, serialize sorted string keys with compact separators/UTF-8/no BOM/no newline/`ensure_ascii=False`/`allow_nan=False`, then store the exact immutable byte sequence alongside schema `v2` and its digest, and link the automation run/decision relationally to report ID/snapshot. Maximum snapshot size is 8 MiB; larger exports fail eligibility. This is a newly defined export boundary, not an existing deployed byte-export API. The initial byte serialization preserves existing report fields and fractional confidence numbers using the Python JSON serializer; every consumer thereafter hashes stored bytes, never regenerates them. The bytes can contain the report's existing fractional confidence numbers; snapshot hashing never parses/re-serializes them. Hashing current mutable detail decorations or a lossy Pydantic dump is forbidden. Snapshot implementation belongs to 16.8; qualification proves exact byte mutation/reformatting changes the digest, not that today's application already stores snapshots. The tuple binds report ID/schema/snapshot digest; provenance has its own content digest and never rewrites report v2. No `v2.1` contract is invented.

The receiver tuple binds workflow/revision/inputs, source and authorization, project/workspace/environment, canonical target/receiver, immutable pipeline revision, report/schema/bytes, passed policy/version/digest, units/waves, screened digests/redaction, exact custody/raw digest when applicable, payload, all deadlines and authorization/restore epochs. Effective expiry is the earliest evidence, approval, collected-source and custody deadline. Receiver messages bind operation ID, tuple digest, `receiver-operation-v1`, monotonically sequenced receipt/outcome and state. Consume must precede counted action and durably consume a one-use grant. `accepted` is not success. Same-operation recovery returns durable state without another action; conflicting binding returns 409. New or resumed action requires current available authority/membership/target/feature/epochs. Any uncertainty holds canonical target lock through cancellation and lease expiry until authorized reconciliation; lock-break never creates authority.

## States, proposed resources and envelopes

Run states: queued, running, waiting_approval, ready_handoff, handing_off, external_running, succeeded, failed, stopped_by_gate, rejected, expired, timed_out, cancelled, delivery_unknown. Attempt states: pending, claimed, running, succeeded, failed, timed_out, cancelled. Gate stop, human rejection, expiry, timeout, cancellation and failure are distinct. Only an authenticated observed terminal receiver outcome can turn external work into succeeded/failed. `delivery_unknown` permits reads, audited reconciliation and cancellation request; it never unlocks or blindly retries. Local safe retry creates a new attempt/fence; it does not reauthorize external work. Later state-machine implementation must validate each transition and predecessor; this freeze defines wire enums, not a deployed transition engine.

The [route matrix](../../tests/fixtures/infra_automation/qualification/16_0/contracts/routes.json) freezes future proposed resources under `/api/v1/infra-automation`, not existing handlers or browser paths. Success uses existing `data`/`meta`. Errors reuse `ApiError`/`build_error` as `{error:{code,message,details:{retryable,correlation_id}}}`. Missing/expired identity is 401; missing capability **or inaccessible scope/object** is generic 403 `Operation unavailable.` without object names, identifiers, logs or existence hints. Stale revision/tuple/idempotency is 409, invalid closed schema 422, quota 429, unavailable current authority 503. Retryable 503/429 permits re-reading/reconciliation after recovery, never blind action resend or decision replay. Every response has a nonsecret correlation ID.

Lists have default 25 and maximum **100 items**, stable descending `(created_at,id)` order, an opaque cursor bound to authenticated principal/scope/filters and a fixed read snapshot. Inserts after snapshot are excluded until a new first-page request; deletions may omit items without duplicates. Revocation is checked on every page, not cached in cursor. Invalid/stale/tampered cursor returns 409; cursor lifetime at most 15 minutes. Logs have per-attempt monotonic sequence and ≤100 chunks/page; `last_sequence`, `gap` and `truncated` are explicit. Gaps never appear as contiguous evidence and require requesting the recorded available range. Terminal/unknown state is separate from log completion.

Permission is the intersection of verified identity, live scope membership, registered role capability and credential audience. Admin publishes/manages targets/enrolls; maintainer/contributor can request authorized published workflows; reviewer/admin/maintainer with review capability decides; read-only only reads. Shared requester is excluded from its own decision. Server-configured single-operator mode permits authenticated acknowledgement with explicit copy, never claims independent review. Agent/service can request/read assigned scope using service-request audience, never decide/publish/admin. Runner and receiver only access their bound machine operations. Scope denial has the same generic 403 as capability denial. Legacy role headers and share URLs are not credentials. Production capability checks, cancellation ownership, membership persistence and object resolution remain 16.2/16.5 obligations.

## Change control

The frozen manifest hashes exact committed schema/fixture bytes and records owners. Any incompatible fields/meaning, new wire states, canonical-byte changes or weakened safety require a new protocol major plus migration. Closed v1 cannot silently accept an additive field. A new capability needs explicit reviewed negotiation, a new registry/content digest and complete safety intersection; otherwise deny. Editorial documentation updates do not rewrite frozen wire digests. Changes to fixture or schema content require rerunning positive/negative/resource and consumer vectors and updating manifest hashes together; old digests remain audit history. A passing prototype does not replace later production identity, transaction, containment, custody or browser acceptance.
