# v1.4.0 security triage before publication

PR#151 compares the accepted development span against production main. Its CodeQL alert check identified 21 annotations; the API additionally listed existing cookie/XSS findings. Analysis-job success is not evidence that those paths are safe. This record captures independent, source-specific triage on 2026-10-07. Query suites and scanning coverage remain enabled.

## Real repaired findings

| Alerts | Root cause | Repair and regression |
| --- | --- | --- |
|90,93| Query names allow `?`, so a failing `&` plus repeated `?!` restarted matching at overlapping suffixes. Doubling input multiplied runtime approximately fourfold. | Consume the complete candidate even without `=`, and ignore credentials only when the capture is `None`. Preserve empty assignments, percent normalization, question marks in sensitive names and multi-parameter behavior. A 32K-unit subprocess regression timed out before repair and completes well within its five-second budget after repair. |
|91| Adjacent whitespace repetitions around an absent optional quote repartitioned a failing authorization prefix quadratically. | One optional quoted branch consumes the second whitespace sequence only when a quote exists. Preserve Bearer/Basic, quoted keys, tabs/spaces and credential collection. The 32K-space subprocess regression timed out before repair and passes after repair. |

After repair, direct 32K-unit query/authorization scans took approximately 0.0005/0.0018 seconds; full redaction plus artifact collection took 0.067/0.047 seconds on the local machine. Timing is machine-specific; regressions retain a generous isolation timeout rather than asserting those exact timings. The focused content/fuzz/performance lane passed 43 tests and 142 subtests. Fresh full local/hosted validation and CodeQL must finish before publication.

## Dependency alert reconciliation

GitHub alerts 1,2,3,5,7 refer to absent root lock entries (`decompress` and old `brace-expansion`). Current main/develop/release root lockfiles contain no such packages. The actual frontend brace-expansion is 2.1.7 and passes a fresh all-severity audit. Clean root `npm ci` removed old extraneous local installs; root/frontend/Python audits report no known advisories. Obsolete root graph findings are classified as inaccurate with source evidence; actual frontend vulnerabilities were repaired rather than dismissed based on a root mismatch.

## Governance and disposition policy

Every remote disposition names the actual guard/test or documented compatibility boundary. Repaired alerts remain open until a fresh scan establishes closure. No broad query exclusion or fake review approval is used. The owner authorized release preparation and best implementation decisions; preserving the minor-release legacy migration contract avoids invalidating existing controlled shares, with its residual risk explicitly documented here and in upgrade notes. Independent human review-policy activation still requires a real reviewer and remains tracked under issue#131.
