## R1 — P2 — Complete response size (AC1), resolved

`services/infra_automation_support.py::bounded_payload` reserved an arbitrary
1,072 bytes for response metadata. A valid 50-step workflow had 119,918 raw bytes,
129,930 canonical bytes and a 130,384-byte complete response, yet creation returned 429
because its 130,274-byte data payload exceeded the undocumented 130,000-byte limit.
All declared ceilings were satisfied.

The helper now measures the complete `data`/`meta` envelope using shared `build_meta`
and a 32-character correlation placeholder, matching the HTTP adapter. It still
runs inside the service transaction. The 128-KiB transport ceiling remains unchanged;
an oversized response rejects before workflow/revision/audit mutations commit.
The contract now explicitly distinguishes canonical-definition and full-envelope limits.
This removes the arbitrary headroom calculation without adding a dependency or protocol.

Regression: `tests/test_api/test_infra_automation_workflows.py::InfraAutomationWorkflowApiTests::test_large_valid_workflow_uses_exact_response_ceiling_and_rolls_back_overflow`.
It failed with 429 before the fix and passes afterward. It exercises large valid
create/save/publish/read, a 131,072-byte successful HTTP response, and one-byte-over
rejection with unchanged workflow and audit rows. The Acceptance Auditor independently
reviewed the implementation, metadata serialization and test; no remaining gap.
